## **tokenization（分词）**：将自然语言拆分成token（词元），所有的token形成一个**vocabulary（词表）**，每个token都有自己的ID
* **词元token**：通常指的是一个文本序列中的最小单元，可以是单词、标点符号、数字、符号或其他类型的语言元素
* 自然语言文本是非结构化的，需要转换为模型可以进行矩阵数值计算的离散整数（token ID）序列
* 基于subword（子词）的分词策略
    * 哲学：将一个没有见过的长单词，拆分为见过的词根、前缀或字母等子词
    * 优势：可以避免**OOV (Out-Of-Vocabulary)**词表无限膨胀的问题，极大地压缩了所需维护的词表空间
    * 主流算法：**BPE（Byte-Pair Encoding, 字节对编码）**、WordPiece、SentencePiece
        * BPE：把频率最高的字节对（Byte-Pair）合并成一个新的 Token，并添加到词表里，反复迭代直到达到设定的词表大小上限
            * **BBPE (Byte-Level BPE)**：所有计算机里的文字，在底层全部都是二进制字节流（UTF-8 编码下任何符号都可以被拆解为 1 到 4 个 Byte，每个 Byte 的取值范围仅为 0x00 ~ 0xFF）
            * 优势：基础词表仅仅 256 个，所有文字都能被拆成这 256 种底层字节。
            * 注意：BBPE并不是只有 256 词表，也是向上合并，最终形成大的词表；对于高频词保证效率压缩，对于低频生僻字确保安全降级不崩溃
        * WordPiece：与 BPE 非常相似也是从底向上合并，根据在一起的概率进行合并，更加符合语言概率论
        * SentencePiece：是一个工业级的 C++ 分词库封装
            优势：把“空格”也当成了一个普通字符，对于中日韩等不需要空格分词的语言尤其友好。可以把原始生肉字符串丢进去训练，不需要任何前置的正则清洗
* **Vocab Size（词表大小）**：关于显存与算力的极限拉扯（Trade-off）
    * 词表很大
        * 优势：节约算力，支持更长的上下文长度（Context Window）。原因：切出来的 Token 粒度大，token序列长度变短
        * 劣势：参数量大，耗费 GPU 显存。原因：Transformer 头部的 Embedding 矩阵尺寸和尾部的输出层都和词表大小有直接关系
    * 词表很小
        * 优势：模型极为紧凑，内存占用小，底层的分类概率好收敛
        * 劣势：序列长度成倍增加，Self-Attention 时的计算灾难，且丧失了深层的语义关联


## **Embedding（嵌入层）**
* **Embedding** 解决的是如何把离散整数序列，转换为‘神经网络能够进行微积分与张量运算的连续空间坐标’
* **One-Hot 向量**：对每个词生成一个 N（词表大小）维的向量，绝大多数位置是 0，只有当前词对应的 ID 位置是 1
    * N 维的极其**稀疏矩阵**会导致内存爆炸，且稀疏矩阵乘法对底层计算极大浪费
    * 任何两个词的向量无论是内积还是余弦相似度全都是 0，即所有词距离相同，**没有语义可言**
* **Dense Vector（稠密向量）**：一个长度固定、每一维都是**连续浮点数**构成的向量
    * 解决稀疏问题：原来分散在 N 空间中的那一个孤立的 1，通过投影压缩到了这 Hidden Size 个浮点数中
    * 解决语义问题：计算稠密向量的数学距离就等同于计算语义距离，两个词语义相近，向量距离越小
    * 高阶亮点：实现语义的代数运算特性，几何加减法则（King - Man + Woman = Queen）
    * **Hidden Size** = 一个 Token 的向量长度（空间维数）
        * Hidden Size 越大，模型能捕捉的语义特征细节就越丰富细腻，代价是矩阵乘法的计算负担和显存占用成平方级往上增
* 任何文本经过 Embedding 层后都会变成长宽为 [序列长度, Hidden Size] 的二维矩阵，进入Transformer Block


## **Transformer Block**
* 输入的数据尺寸是 [序列长度, Hidden Size]，输出的结果数据矩阵大小还是 [序列长度, Hidden Size]，因此可以进行串联
* 内部结构：
    * **Normalization (归一化)**：在数据进入下一个计算节点前，按比例拉伸或压缩回一个稳态的分布区间
        * 主流实现（**Pre-LN**）：输入数据进入那一层的 Transformer Block 之后，首先第一步就去做归一化
        * 作用
            * 前向传播：防止数值爆炸或数值消失，保证计算安全
            * 反向传播：在训练阶段更新参数时，稳定的数值分布能保证“损失梯度”极其平滑，使得模型收敛
            * 实现超深网络：使得 **Transformer 能够串联堆叠**几十甚至上百层
        * 算子
            * 为什么不同BatchNorm：输入矩阵大小不同（主要是，序列长度不同），不像CV中图像可以处理成统一大小
            * 为什么不用LayerNorm：
                * LayerNorm：先遍历一遍所有数据求出均值，然后所有数字减去均值；再遍历数据求出方差，除以方差缩放
                * 在极深的网络里，“减去均值”这个动作对于稳定模型收敛毫无任何实际帮助；真正管用的，只有“除以方差”的缩放克制操作
            * **RMSNorm(均方根归一化)**：每一项全部平方相加，除以长度后再开根号；拿着所有的旧数据，直接除以这个 RMS 值；保留可学习的参数项 gamma 用来动态缩放
                * 优势：**不用算均值了**，每个token独立计算
                    * 在 GPU 计算中，节省了针对同一块显存数据的 1 次**重复读写**，把 CUDA 算子的读写复杂度降低
                    * 在分布式大模型张量并行（TP）运算中，节省了 1 次显卡之间**All-Reduce 通信次数**，把等待通信的延迟降低

    * **Self-Attention (自注意力)**：实现了全局上下文融合，让多义词有了明确的含义，每个 Token 向量里都杂交了其他 Token 一定比例的特征
        * 输入：归一化后的数据矩阵，大小为 [序列长度, Hidden Size]
        * 输出：Q K V 计算之后的数据矩阵，大小仍然为 [序列长度, Hidden Size]，因此可以进行串联搭建
        * **Q K V矩阵**：输入矩阵分别和尺寸为 [Hidden Size, Hidden Size] 的权值矩阵 w_q，w_k，w_v 做乘法，大小仍为 [序列长度, Hidden Size]
            * 权值矩阵：初始化是随机数，训练时产生的误差反向传播回来，优化器 AdamW 对权值矩阵进行优化
            * Q (Query / 查询矩阵)：表示每个 token “想找什么其他特征的词”
            * K (Key / 键矩阵)：表示每个 token “自己带有什么特征”
            * V (Value / 值矩阵)：表示每个 token “实际包含的语义信息”
            * **RoPE（旋转位置编码 - Rotary Position Embedding）**
                * 位置：Q \times K^T之前对 Q 和 K 进行
                * 机制：一个token的向量为 [q1, q2, q3, q4 ...... q4095, q4096]
                    1. 两两配对（构建坐标系）：(q1, q2) 是一对，(q3, q4) 是一对...，每一对可以看作一个“指针”
                    2. 施加旋转（Rotation）：这个 token 是序列中第 m 个，则其第 i 根指针旋转 m * i 度
                * 核心：Q \times K^T$ 算内积时，结果只与**相对距离差**（有正负）有关
                    * 让模型知道每个token的先后顺序
                    * 赋予顶级外推性（Extrapolation）：让大模型（如 LLaMA）拥有极强的长文本泛化能力
            * **注意力计算公式**：$\text{Attention} = \text{Softmax}(\frac{Q \times K^T}{\sqrt{Hidden Size}}) \times V$
                * Q \times K^T：得到 **Raw Attention Scores**
                * 缩放 (Scale)：将 Raw Attention Scores 每个元素都除以 \sqrt{Hidden Size} —— 防数值溢出
                * 因果掩码 (Causal Masking)：Raw Attention Scores加上一个遮罩，确保第 i 个 Token 只能看到 前 i 的历史 Token
                * 归一化 (Softmax)：对 Raw Attention Scores 矩阵中的每一行分别进行Softmax，得到**注意力权重矩阵 Attention Weights**
                * 乘以 Value 矩阵：Attention Weights 和 V 矩阵做乘法，每个token的结果就是前面token的**加权求和**
        * 显存占用：Q \times K^T的结果是一个大小为 [序列长度, 序列长度] 的中间产物，随着输入文本序列的长度平方级增长，极大消耗显存
            * 训练阶段，使用**FlashAttention**：不落盘在 GPU 的 SRAM 缓存中计算（如 Kimi、Claude 200k）
            * 推理阶段，主要的问题是KV Cache 积累变大，使用 MQA/GQA 架构优化 与 **PagedAttention**

        * **MHA (Multi-Head Attention / 多头注意力)**：对输入矩阵进行纵向切分成 32 块后，每块小矩阵大小为[序列长度, Hidden Size / 32]，分别计算各自的QKV后再 concat 恢复大小
            * 作用：多头机制让模型具备了在同一个时刻，从十几个完全不同的抽象几何维度“多任务同时理解”世界的能力
            * 性能：训练时在 GPU 上消耗算力和物理耗时完全一致；推理解码阶段，**KV Cache**容易导致**显存容量爆表和内存带宽卡死**
        * **MQA (Multi-Query Attention / 多查询注意力)**：只准用 1 套 K 头和 1 套 V 头
            * 好处：存下来的 KV Cache 缓存大小直接暴跌 32 倍，推理时生成结果速度很快
            * 坏处：所有的 Q 都在找同一套 K，模型的表达广度和智商出现了肉眼可见的大幅下降
        * **GQA (Grouped-Query Attention / 分组查询注意力)**：折中方案，分成 8 组，就是每 4 个 Q 头共同分享 1 套 K 和 V
            * 好处：存下来的 KV Cache 缓存大小直接下降为原版 MHA 的 25%
            * 坏处：GQA 的智商与效果几乎完美持平最原始庞大的 MHA

    * **Residual Connection（残差连接）**：所有的模块都是在模型主干道上开一个分支计算残差，最后合并回主干道
        * 物理公式：x_out = x_in + F(x_in)，F(x_in)就是残差
        * 优势：加法（+）操作可以将误差反馈的梯度无损倒流分发，解决反向传播中梯度消失的问题，开辟了一条贯穿前后的**梯度信息高速公路（Gradient Highway）**
        * 位置： **Residual Add 1** (Attention 之后)：原始特征主干道 $X$ + Attention 提取出的上下文关系差值 $\to$ $X_{mid}$。
                **Residual Add 2** (FFN 之后)：新主干道 $X_{mid}$ + FFN 提炼出的高维常识差值 $\to$ $X_{out}$

    * **FFN (前馈网络)**：独立处理每个token，获取每个token特有的常识特征（FFN 几乎稳定占据了整个大模型 2/3 的参数量和计算量）
        * 输入：Attention模块的输出经过一次旁路相加（Residual Add 1）和一次归一化（Pre-LN）的矩阵，大小为 [序列长度, Hidden Size]
        * 输出：经过升维、激活、降维后，矩阵中每个token被赋予了常识和世界知识的特征，大小保持为 [序列长度, Hidden Size]
        * **升维**：输入矩阵和 up_proj 做乘法，将维度扩展到更高维空间 **intermediate_size**，token的所有常识特征都被暴露出来
            * up_proj（Up Projection）升维投射权值矩阵：[Hidden Size, intermediate_size]，和 FFN 的输入矩阵相乘
                * 为什么 intermediate_size 不是 Hidden Size 的整数倍
                    1. 在 GPT2 时是 4 倍，在 Llama 后由于使用了 SwiGLU，FFN 内部多出了一个专门平行的 gate_proj 矩阵，如果还是 4 倍，模型的计算和占用显存过多，因此改为**8 / 3**的比例
                    2. 在 GPU 的底层计算逻辑中，由于矩阵切块优化，如果矩阵尺寸不是完美倍数，算力利用效率会暴跌。为了在硬件层面上对齐，在乘完比例后，架构师人为地把它往上取整为一个完美的能被除尽的倍数上（比如 14336 或 11008）
        * **激活**： 对暴露出来的所有常识特征中进行**过滤**，获取更佳精准的语义特征
            * gate_proj（Gate Projection）门控投射权值矩阵：[Hidden Size, intermediate_size]，和 FFN 的输入矩阵相乘
            * **SwiGLU 门控机制**
                * 和 gate_proj 相乘之后的高维矩阵，经过 Swish 激活函数变为一张特征过滤遮罩（Mask），最后和升维后的矩阵做**逐点相乘（Hadamard Product）**，动态过滤升维后暴露出来的特征
                * **Swish 激活函数**：Swish(x) = x * Sigmoid(x)。Sigmoid是一个概率函数，输出 0 到 1 之间的百分比概率，再乘以原始 x 进行门控
            * 为什么不用传统 ReLU：大于 0 的特征原封不动放行，小于 0 的特征一刀切为 0
                1. 梯度平滑连续，更容易收敛
                2. 在 $x < 0$ 的一小段区域内，Swish 是先减后增的，允许模型保留一些小的负值信息，增强了表达能力
        * **降维**：激活后的精准语义特征矩阵大小为[序列长度, Hidden Size]，需要和 down_proj 进行矩阵乘法，将尺寸恢复回[序列长度, Hidden Size]
            * down_proj（Down Projection）降维投射权值矩阵：[intermediate_size, Hidden Size]



## **LM Head（语言建模头 / 输出解算层）**
* 输入：从最后一层 Transformer Block 吐出来的那个 [序列长度, Hidden Size] 的高维矩阵
* 步骤
    * 只取最末尾的token对应的向量 **last_hidden_state**，大小为[1, Hidden Size]：浓缩了前面所有文本的终极因果语义
    * 过一遍专属的最终归一化（Final RMSNorm），大小还是[1, Hidden Size]
        * 残差极度膨胀：每一层的归一化（RMSNorm）只局限于进 FFN 和 Attention 的旁路，主路的数值规模（方差与绝对值）极度膨胀
        * 防止 LM Head 和 Softmax 物理宕机（避免 NaN 与极化）
    * 和**LM Head**矩阵相乘，得到[1, 词表大小]的行向量，里面是词表大小个数的**Logits**分数，输入到 **Softmax** 激活函数，压缩成了介于 0 到 1 之间的 概率表（它们的概率总和等于 100%）
        * LM Head权重矩阵（又叫 Un-embedding 矩阵）：大小为[Hidden Size, 词表大小]
    * 惩罚器：防止出现死循环复读
        * repeat-last-n (惩罚判定窗口)：回看刚刚吐出来的最后 $N$ 个 Token（比如 N=64）
        * repeat-penalty（乘法缩放减伤）：如果 Token 在窗口里出现过，我就把它原本的 Logit（原始概率得分）直接除以一个系数（比如 1.1）
        * frequency-penalty（按次数递增惩罚）：新概率 = 原概率 - (出现次数 × 惩罚强度)
        * presence-penalty：只要你在窗口里曾经出现过至少一次，就被扣除固定的常数分数
        * DRY（Don't Repeat Yourself）：DRY 算法不盯单字，它盯序列的模式（Pattern）
            * 过度惩罚：模型连最基本的“的”、“了”、“我”都不敢用了，导致语句极度不通顺
    * 使用Temperature (温度系数)、Top-K / Top-P (核采样截断) 等操作，从概率表中选出一个token
        * 贪心解码（Greedy Search）：永远且唯一只挑选概率排在全表第 1 绝对第一名的那个字
            * 效果：输出是 100% 确定性的。丢给它 10 次同样的 Prompt，它吐出来的回答一字不差
            * 适合极其严谨、答案唯一的任务（如算数学题、写代码）；但在写文章聊天时，极度容易陷入死循环，极其缺乏人类的创造力
        * 温度系数（Temperature）：在做 Softmax 算百分比之前，先把那个庞大的 Logits 分数除以一个值 $T$（温度）
            * 效果： 当 $T < 1$ 时（低温，如 0.1）：分数之间的差距会被极度拉大，极其趋近于上面的贪心解码
                    当 $T > 1$ 时（高温，如 2.0）：分数之间的差距会被极度缩小，模型变得创造力爆表，但也极其容易前言不搭后语
        * Top-K 截断采样：把概率排名前 K 个作为候选池，把它们的概率重新洗牌凑到 100%，再重新抽签
            * 效果：有效防止了抽出低质量字，但是太死板了
        * **Top-P 核采样（Nucleus Sampling）**：划定一个概率红线 $P$，从第一名开始往后加，直到候选人的概率总计刚好达到 90% 的门槛
            * 效果：行业主流，当模型极度自信时只保留 1 个选项，当模型极度纠结发散时只保留多个选项
        * **min-P 采样**：根据最高概率 Token 的概率来动态设定门槛（阈值 = P_max * p）p 一般为0.05 到 0.1
    * 这个token单独再进入模型进行计算，在Transformer Block中生成自己的Q矩阵，去显存硬盘（**KV Cache**）调取历史的 K 和 V 矩阵

## **自回归循环**：模型每次只能预测输出一个字，并把这个字加入到上一次的输入中进行循环预测
    * EOS（End Of Sequence / 序列结束符）：<|EOS|>是词表中一个特殊隐藏指令 Token，模型在训练后能输出 EOS让自回归循环停止

## 反向传播
* **交叉熵损失（Cross-Entropy Loss）**：模型预测答案（Predict）和真实标准答案（Target）的差距
    * 负对数原理 $-\log(P_{true})$ ：P_{true}是模型给Target计算得到的概率，概率越小，loss越大
* 残差连接利用微积分的求导链式法则，将 Loss 无损传导到各层Transformer Block中的 Attention 和 FFN，使用AdamW 优化器优化参数


## 权值绑定
* 背景痛点：Embedding 矩阵和LM Head 矩阵，极其庞大的参数显存开销
* **权值绑定**：Embedding 矩阵和LM Head 矩阵在数学上互为镜像（互为转置结构），直接使用物理内存里“同一块硬盘区域的同一组参数数字”
* **解除绑定（Untied）**：两个矩阵完全解绑各自进化，能给大模型提供额外巨大的自由表达智商，用不到 1GB 的显存换取更高的测试集评分


## 推理（Inference）生命周期
* 预处理：调用分词器（Tokenizer）将用户输入的 Prompt 切分，并映射成模型词表中对应的 Token ID 序列
* **预填充（prefill）**：将token ID 序列转换为 Embedding 向量，一次性进行注意力计算，并将 K 和 V 矩阵保存在显存，完成 KV Cache 的创建，并输出第一个新token
    * 计算特征：**GEMM（通用矩阵乘矩阵）**，**Compute-bound（算力受限）**
    * 核心指标：TTFT (Time To First Token，首字延迟)
* **解码（Decoding）**：将生成的新token作为输入，计算Q K V，并将新token的 K V 追加(Append)到 KV Cache 末尾，读取 KV Cache 进行注意力计算并输出新token，重复直到结束
    * 计算特征：**GEMV（通用矩阵乘向量）**，**Memory-bound（访存受限）**，需要将 KV Cache 从显存（HBM）移动到计算核心（Tensor Core）的片上缓存（SRAM）
    * 核心指标：TPOT (Time Per Output Token，每输出 Token 耗时)
* 后处理：停止 GPU 上的解码循环。将生成的所有 Token 通过分词器反向转换（Detokenize）为字符串，最后释放占用的 KV Cache 显存
* 超参数调控
    * -ngl / --n-gpu-layers：卸载到 GPU 的层数。越多速度越快，但需要更多显存
        * 对性能影响最大：能全放GPU就全放，因为数据要通过PCIe总线在GPU和CPU之间来回搬远，效率极慢
    * -b (Batch) 和 -ub (U-Batch)：只在 Prefill 阶段起作用优化吞吐量
        * -b (逻辑批处理)：Prompt 预处理阶段一次能并行处理的 Token 数
        * -ub (物理批处理)：实际提交给显卡/CPU 计算的切片大小。通常和 -b 相等，如果显存极其吃紧，可以调小
        * 影响：调节首字响应时间和显存用量
    * -c / --ctx-size（上下文窗口）：决定了模型对对话准备多少 token 的 KV Cache
    * -t / --threads（CPU 线程数）：通常设为你的物理核心数
    * --flash-attn：是否启用 Flash Attention。能大幅降低长文本下的显存占用并提升速度。


## **KV Cache**
* **背景**：大模型推理采用**自回归循环**，每次只生成 1 个新 token，但新 token 的 Q 矩阵需要和所有历史 token 的 K、V 矩阵做注意力运算
* **问题根源（无 Cache）**：如果不缓存，每生成一个新 token，就必须对整个历史序列**重新计算**一遍 K、V，大量计算被白白浪费（已生成的 token 的 K、V 值永远不变）
* **KV Cache 核心机制**：把每一层 Transformer Block 中，历史 token 的 K 矩阵和 V 矩阵**持久化缓存在显存**里，解码时直接复用
    * 每生成 1 个新 token，只需计算该 token 自己的 Q、K、V
    * 新 token 的 K、V **追加** 到 KV Cache 末尾
    * 新 token 的 Q 直接与 Cache 中完整的 K、V 做注意力运算，得到输出
    * **不再重复计算**历史 token 的 K、V，节省大量算力
* **显存开销分析**（以 LLaMA-2 7B 为例，FP16）
    * 单层单 token 的 KV Cache 大小 = 2（K+V）× num_heads × head_dim × 2bytes
    * 累计公式：`KV Cache 总量 = num_layers × 2 × num_heads × head_dim × seq_len × 2bytes`
    * 例：32层 × 2 × 32头 × 128维 × 2048 token × 2bytes ≈ **1 GB**，随序列长度**线性增长**
* **KV Cache 的两大工程瓶颈**
    * **显存容量爆表**：长对话、长文档场景下 seq_len 不断增长，KV Cache 持续膨胀，甚至超出单卡物理显存上限
    * **内存带宽卡死**：每次 Decode 都要把全量 KV Cache 从 HBM（显存）搬到 SRAM（片上缓存），搬运量远大于实际计算量，GPU 算力大量空转等数据
* **工程优化方案**
    * **MQA / GQA**：从源头缩减 KV Cache 的数据量（参见 MHA/MQA/GQA 章节）
    * **量化（Quantization）**：将 KV Cache 从 FP16 量化为 INT8 甚至 INT4
        * 好处：显存占用体积直接压缩 2~4 倍
        * 坏处：当 GPU 计算（Q × K^T）时，需要在流处理器（SRAM）里临时反向解压缩回 FP16（Dequantization），导致略微的计算延迟，且极度压缩（如 INT4）可能会导致最终回答的智商由于精度损失有轻微下降
    * **Offloading(异构卸载/内存换页)**：将暂时不用的 KV Cache 页换出到 CPU 内存
        * 好处：用时间（搬运延迟）换空间（巨大容量）
        * 坏处：卡顿延迟，拖慢 TPOT (每输出一个字的耗时)
    * **vLLM**：开源的大模型推理和部署（Serving）框架
        * **PagedAttention**：将 KV Cache 按"页（Page）"分块动态分配，类似操作系统的虚拟内存管理
        * 解决碎片化：传统连续分配导致大量显存碎片浪费，PagedAttention 将 KV Cache 切成固定大小的 Block，按需申请/释放
            * 优势：**显存碎片率趋近于零**，系统吞吐量翻倍，即单卡能同时处理更多请求（Batch Size 增大）
            * **Batch Size 增大**的好处：对于模型权重参数，GPU搬运耗时较长但能用于处理更多的请求；对于 KV Cache 充分利用显存带宽（Bandwidth）
        * 支持**连续批处理，Continuous Batching**：不同请求的 KV Cache 长度不同，分页后可以高效地在同一显存池中**混合调度多个请求**
            * 静态批处理（Static Batching）每次都等同一批所有请求都完成GPU才接受下一批，造成算力浪费
            * 连续批处理（Continuous Batching）同一批中的不同任务，先完成的退出GPU，未完成的继续执行的同时新任务插入到当前的batch中
        * 支持 Prefix Sharing：多个请求共享相同前缀（如 System Prompt）时，KV Cache 页可以**物理共享内存**，不需要每个请求都复制一份和搬运一次，节省了显存和带宽
            * **Copy-on-Write（写时复制）**：只有写入数据时，系统才会单独复制一份
                * CoW 是 **Block-level（块级别）**的，只有当新生成的 token 的 KV 需要写入一个**半满且被共享**的物理块末尾时，才会对这一个物理块触发写时复制，其他**写满**的共享块不受影响



## **算子融合(Kernel Fusion)**
    * 把计算图中多个关联的算子，揉成一个“超级算子” (生成一个聚合的 CUDA Kernel)
    * 原理：在GPU上，运算时间极短，但是将数据从 HBM 搬运到 SRAM 花费更多时间
    * 收益：减少数据搬运次数，释放显存带宽


## **FlashAttention**
* **Tiling (分块)**：把 Q, K, V 切成一块块 Block，每次只把一小块 $Q_{block}$，和一小块 $K_{block}$、$V_{block}$ 从 HBM 搬到 SRAM 里
* **Online Softmax**
    * 传统 Safe Softmax：
        * 第一遍遍历：扫描所有 $N$ 个元素，找出全局最大值 $m$
        * 第二遍遍历：计算每个元素的指数 $e^{x_i - m}$，并求出全局分母（指数和）$l = \sum e^{x_i - m}$
        * 第三遍遍历：用每个指数除以分母 $l$，得到最终概率 $P_i$。
    * Online Softmax：维护了两个全部变量 m 局部最大值 和 l 局部指数和，在遍历每一个block时，计算修正因子(Scaling Factor) 不断修正历史结果，最终结果和传统 Safe Softmax 完全一致
        * 优势：使得softmax的计算不再需要依赖全局，可以分块局部处理，把 Softmax -> 乘 V 这两步可以融进同一个 SRAM 循环里
* 本质是不写回主显存： 它把 $QK^T \rightarrow Scale \rightarrow Mask \rightarrow Softmax \rightarrow 乘 V$ 这所有步骤，融合在一个巨大的 CUDA 算子里完成。巨大的中间矩阵完全在 SRAM 这个黑盒里消化掉了，它根本不曾被写出到物理显存 HBM 过
* **Recompute (重计算)**：用廉价的计算（Compute）去置换昂贵的访存（Memory IO）
    * FlashAttention 会把每一行算出来的最终的最大值 $m$ 和最终的总分母 $l$ 作为一个小小的向量写回到显存中保存起来
    * 把对应的 $Q$、$K$ 块以及 $m$ 和 $l$ 再次从 HBM 读进极速缓存 SRAM 中重新计算局部的概率矩阵
    * 在反向传播时算完当前 block 的梯度时直接丢弃

## **分布式训练**
    数据并行：在反向传播过程中，需要对各个设备上的梯度进行AllReduce，以确保各个设备上的模型始终保持一致。当数据集较大，模型较小时，由于反向过程中为同步梯度产生的通信代价较小，此时选择数据并行一般比较有优势
    张量并行：当神经网络非常巨大，数据并行同步梯度的代价就会很大。每个设备上的数据是完整的、一致的，而模型被切分到了各个设备上，每个设备只拥有模型的一部分，所有计算设备上的模型拼在一起，才是完整的模型。
    流水并行：将网络切为多个阶段，并分发到不同的计算设备上，各个计算设备之间以“接力”的方式完成训练
    混合并行：多种并行策略混用
